# Голосовое управление Atlas через Discord

Atlas подключается к одному голосовому каналу Discord, слушает только одного указанного пользователя и после паузы примерно 0,8 секунды отправляет фрагмент речи в OpenRouter Speech-to-Text. Нажимать клавишу для записи не требуется. Распознанная речь запускает планирование действий Atlas с приоритетом команды оператора. При включённом `DISCORD_TTS_ENABLED=true` бот произносит подтверждение и свои ответы в том же канале. Это обработка коротких фраз по мере их завершения, а не пословная трансляция с нулевой задержкой.

## Что нужно сделать в Discord

1. Создайте свой сервер и обычный **голосовой канал**.
2. В [Discord Developer Portal](https://discord.com/developers/applications) создайте приложение, откройте вкладку **Bot** и получите **Bot Token**. Не присылайте его в публичный чат и не добавляйте в Git.
3. Во вкладке **Installation** включите установку на сервер, область `bot` и разрешения **View Channels**, **Connect**, **Speak**. Установите бота на свой сервер. Привилегированный **Message Content Intent** для голосового канала не требуется.
4. В настройках Discord включите **Режим разработчика**. Через контекстное меню скопируйте ID сервера, голосового канала и своего пользователя.
5. В локальном файле `.env` проекта заполните `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID`, `DISCORD_VOICE_CHANNEL_ID`, `DISCORD_ALLOWED_USER_ID`. Укажите именно свой user ID: речь остальных участников не будет отправляться на распознавание.

Когда данные готовы, запустите Paper и `npm start` согласно [основной инструкции](SETUP_DGX_SPARK.md). Бот сам войдёт в настроенный голосовой канал. Зайдите туда с Windows и скажите, например: «Атлас, собери дерево». В журнале сервиса появится строка `[Discord] ID: ...` с расшифровкой, затем Atlas получит её как сообщение. Ответ прозвучит через Discord, если TTS включён.

Команда «Атлас, следуй за мной» включает непрерывное следование за первым игроком из `BOT_COMMAND_WHITELIST`. Игрок должен быть виден Atlas в Minecraft; бот не телепортируется. Команда «Атлас, стой» прекращает следование и возвращает автономное поведение. Другая голосовая команда также прекращает следование перед новым заданием. Если оператор остаётся в канале, но входящий звук не поступает две минуты, голосовое соединение обновляется автоматически.

Если на машине задан `HTTPS_PROXY`, команда `npm start` направляет через него подключения к Discord API и голосовому WebSocket. Для обычных голосовых каналов установлены актуальная версия `@discordjs/voice` и модуль DAVE: старые голосовые клиенты Discord отклоняет с кодом 4017.

Используется тот же `OPENAI_API_KEY` OpenRouter, что и для решений Atlas. По умолчанию: `openai/whisper-large-v3` для русского STT и `mistralai/voxtral-mini-tts-3-0` с голосом `voice_3150` для речи. Модели и доступность проверяйте в [OpenRouter Speech-to-Text](https://openrouter.ai/docs/guides/overview/multimodal/stt) и [Text-to-Speech](https://openrouter.ai/docs/guides/overview/multimodal/tts); каждый фрагмент и голосовой ответ могут тарифицироваться отдельно. Для отключения голосовых ответов задайте `DISCORD_TTS_ENABLED=false`.

Захват ограничен 12 секундами на фрагмент; очень короткие звуки пропускаются. При проблемах с подключением проверьте ID и права бота, доступ к Discord с Spark и строки `[Discord]` в журнале. Получение звука в `@discordjs/voice` зависит от недокументированного Discord Voice API, поэтому его поведение может измениться после обновления Discord.

## Когда Spark не получает звук Discord

Если Discord показывает, что вы говорите, а на Spark нет строк `[Discord] Captured ...`, запустите приём голосового канала на Windows. На этой машине подготовлен игнорируемый Git файл `windows-voice.env` только с нужными настройками Discord, OpenRouter и секретом локального канала связи. Токены не публикуйте в Git.

1. На Spark установите `DISCORD_VOICE_REMOTE=true` в `.env` и перезапустите `npm start`. Появится строка `[Discord relay] Listening on port 3090`. Minecraft и планирование продолжают работать на Spark.
2. На Windows установите Node.js **22.12+**, склонируйте этот репозиторий и запустите `npm ci` в каталоге проекта. Скопируйте подготовленный `windows-voice.env` со Spark в `.env` каталога Windows. Файл содержит секреты, поэтому передавайте его через свой защищённый доступ к Spark (например, скачайте файл из удалённой IDE), а не через Git или чат.
3. Для голосовых ответов установите `ffmpeg` и добавьте его в `PATH`. При отсутствии `ffmpeg` распознавание и команды работают, но воспроизведение ответа завершится ошибкой.
4. Запустите в Windows PowerShell `npm run voice:windows`. Бот войдёт в тот же голосовой канал. Короткий фрагмент речи отправится на OpenRouter STT, текст — по локальному HTTP с секретом на Spark, а подтверждение прозвучит из Windows-процесса.

`VOICE_BRIDGE_URL` в Windows-файле по умолчанию указывает на `http://192.168.217.91:3090/voice-command`. Если адрес Spark в вашей сети другой, измените его. Windows и Spark должны видеть друг друга по локальной сети. При `DISCORD_VOICE_REMOTE=true` Spark сам не входит в голосовой канал.
