# Голосовое управление Atlas через Discord

Atlas подключается к одному голосовому каналу Discord, слушает только одного указанного пользователя и после паузы примерно 0,8 секунды отправляет фрагмент речи в OpenRouter Speech-to-Text. Нажимать клавишу для записи не требуется. Распознанный текст поступает в очередь сообщений Atlas так же, как сообщение в игровом чате. При включённом `DISCORD_TTS_ENABLED=true` бот произносит подтверждение и свои ответы в том же канале. Это обработка коротких фраз по мере их завершения, а не пословная трансляция с нулевой задержкой.

## Что нужно сделать в Discord

1. Создайте свой сервер и обычный **голосовой канал**.
2. В [Discord Developer Portal](https://discord.com/developers/applications) создайте приложение, откройте вкладку **Bot** и получите **Bot Token**. Не присылайте его в публичный чат и не добавляйте в Git.
3. Во вкладке **Installation** включите установку на сервер, область `bot` и разрешения **View Channels**, **Connect**, **Speak**. Установите бота на свой сервер. Привилегированный **Message Content Intent** для голосового канала не требуется.
4. В настройках Discord включите **Режим разработчика**. Через контекстное меню скопируйте ID сервера, голосового канала и своего пользователя.
5. В локальном файле `.env` проекта заполните `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID`, `DISCORD_VOICE_CHANNEL_ID`, `DISCORD_ALLOWED_USER_ID`. Укажите именно свой user ID: речь остальных участников не будет отправляться на распознавание.

Когда данные готовы, запустите Paper и `npm start` согласно [основной инструкции](SETUP_DGX_SPARK.md). Бот сам войдёт в настроенный голосовой канал. Зайдите туда с Windows и скажите, например: «Атлас, собери дерево». В журнале сервиса появится строка `[Discord] ID: ...` с расшифровкой, затем Atlas получит её как сообщение. Ответ прозвучит через Discord, если TTS включён.

Если на машине задан `HTTPS_PROXY`, команда `npm start` направляет через него подключения к Discord API и голосовому WebSocket. Для обычных голосовых каналов установлены актуальная версия `@discordjs/voice` и модуль DAVE: старые голосовые клиенты Discord отклоняет с кодом 4017.

Прокси `127.0.0.1:8080` принимает HTTP/HTTPS и WebSocket. Голосовые пакеты Discord передаются по UDP напрямую: обычный HTTP-прокси их не туннелирует. Поэтому строка `Voice connection ready` подтверждает подключение сигнального канала, но не получение речи. Во время проверки смотрите `Speech started`, `Speech ended`, `STT response`, `TTS response` и `Voice playback finished`. Каждые 30 секунд, пока оператор в канале, выводится число полученных UDP-пакетов. Если оно не растёт во время речи, проблема возникает до распознавания и OpenRouter.

Используется тот же `OPENAI_API_KEY` OpenRouter, что и для решений Atlas. По умолчанию: `openai/whisper-large-v3` для русского STT и `mistralai/voxtral-mini-tts-3-0` с голосом `voice_3150` для речи. Модели и доступность проверяйте в [OpenRouter Speech-to-Text](https://openrouter.ai/docs/guides/overview/multimodal/stt) и [Text-to-Speech](https://openrouter.ai/docs/guides/overview/multimodal/tts); каждый фрагмент и голосовой ответ могут тарифицироваться отдельно. Для отключения голосовых ответов задайте `DISCORD_TTS_ENABLED=false`.

Захват ограничен 12 секундами на фрагмент; очень короткие звуки пропускаются. При проблемах с подключением проверьте ID и права бота, доступ к Discord с Spark и строки `[Discord]` в журнале. Получение звука в `@discordjs/voice` зависит от недокументированного Discord Voice API, поэтому его поведение может измениться после обновления Discord.
